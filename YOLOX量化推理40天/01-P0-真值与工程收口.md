# P0 · 真值与工程收口（D1–D2）

> [!info] 阶段定位
> 先建立“真值”和“可重复的基准”，后面所有算子、量化、CUDA 都拿它做对拍。这个阶段不追求性能，只追求**可复现**和**可对比**。

> [!note] 机器：Mac（M5 Pro）
> P0–P3 都在 Mac 上完成；CUDA 阶段在 P4 之后切到 N 卡机器。双机同步见 [[11-双机Git工作流]]。

> [!note] 手搓区
> 下面提到的 `核心框架/`、`验证工具/` 脚本都是你自己的手搓草稿；跑它们是为了建立基线，不是依赖现成工具。

## 阶段目标

- 把 `模型/yolox_s.onnx` 的真实结构、输入输出、算子、权重、FLOPs 弄清楚。
- 用 ONNXRuntime 保存固定输入/输出，作为后续 NumPy/CUDA 的对拍基准。
- 把现有的 DAG 脚本、验证脚本修到能跑。
- 建立最小的 `tools/`、`src/`、`tests/` 目录约定。

## 硬验收标准

- [ ] `python tools/inspect_onnx.py` 能打印 279 节点、10 类算子、176 initializers、8.96M 参数、26.69 GFLOPs。
- [ ] `ref_input.npy` / `ref_output.npy` 已保存，shape 分别为 (1,3,640,640) / (1,8400,85)。
- [ ] `src/onnx_loader.py` 能解析 279 个节点，拓扑排序长度 279，无环。
- [ ] `DAG学习/yolox_s_full_dag.py` 在自身目录下可运行。
- [ ] 记录 ORT 基线延迟（warmup + 5 次平均）。

> [!warning] 不通过就不要进 P1
> 如果节点数不是 279、输出不是 1×8400×85，先查模型文件和解析逻辑，不要往下写算子。

## 每日任务

- [ ] 建目录：`tools/`、`src/`、`tests/`。
- [ ] 写 `tools/inspect_onnx.py`：打印 ir_version、opset、inputs、outputs、node 数、op 类型统计、initializer 数、dtype、参数量、FLOPs。
- [ ] 用固定 seed 生成输入，跑 ORT，保存 `ref_input.npy`、`ref_output.npy`。
- [ ] 跑现有脚本，记录结果：`核心框架/numpy_framework.py`、`验证工具/test_ops.py`、`验证工具/verify_vs_torch.py`、`DAG学习/yolox_s_full_dag.py`。
- [ ] 修 `DAG学习/yolox_s_full_dag.py` 的绝对路径（改成 `Path(__file__).parent`）。

**完成标志**：模型摘要、参考 npy、基线延迟三项都有。

### D2 · 逐层参考 + ONNX 解析

- [ ] 写 `tools/dump_ort.py`：把每个 node 的输出临时加进 `graph.output`，用 ORT 跑出逐层张量；至少保存 Conv/Add/Concat/Resize 的输出。
- [ ] 写 `src/onnx_loader.py`：解析 node、attribute、initializer；int64 常量单独存；加虚拟 input/output 节点。
- [ ] 实现拓扑排序，输出 279 个节点；验证无环。
- [ ] 打印前 10/后 10 个节点及 shape，确认 Focus 是 8 个 Slice + 1 个 Concat。
- [ ] 和 `DAG学习/yolox_s_full_edges.json` 的 279 节点对照，记录差异。

**完成标志**：逐层参考可 dump；loader 能给出合法拓扑序；差异有记录。
