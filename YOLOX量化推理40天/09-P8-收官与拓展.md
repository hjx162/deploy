# P8 · 收官与拓展（D36–D40）

> [!info] 阶段定位
> 把项目收成一个能讲、能复现、能继续迭代的作品。对比生产框架，选一个进阶方向，写总结，制定下一个 90 天计划。不要开新坑，先把已有内容讲清楚。

> [!note] 机器：任一
> 总结、文档、博客可在 Mac；最终 CUDA demo 建议在 N 卡机器跑并记录 GPU/延迟。D40 结束前 push + tag `v1.0`。详见 [[11-双机Git工作流]]。

## 阶段目标

- 对比 TensorRT/OpenVINO/TVM，理解生产框架的取舍。
- 选一个进阶方向做小实验（Winograd、implicit GEMM、CUDA Graph、GPU NMS、INT4）。
- 最终 demo：图片/视频，延迟/精度表。
- 从零讲一遍：YOLOX 结构、ONNX、量化、CUDA kernel。
- 复盘 40 天，制定下一个 90 天计划。

## 每日任务

### D36 · 生产框架对比

- [ ] 读 TensorRT/OpenVINO/TVM 的推理流程：图优化、量化、kernel 选择。
- [ ] 选 YOLOX-s 跑一次 TensorRT（如果能装），记录延迟/精度。
- [ ] 对比你的框架：差在哪？是 kernel、图优化、还是工程化？
- [ ] 写一页对比笔记，不要只列功能，要写取舍。
- [ ] 记录“哪些能学，哪些不适合 40 天项目”。

**完成标志**：能说清楚“生产框架比你多做了什么”。

### D37 · 进阶小实验

- [ ] 五选一：Winograd、implicit GEMM、CUDA Graph、GPU NMS、INT4。
- [ ] 定一个最小目标：比如 Winograd 只做 3×3、单层对拍；CUDA Graph 只减少 launch 开销。
- [ ] 做实验、记录数据；失败也算结果。
- [ ] 写一页报告：动机、做法、收益、坑。
- [ ] 不要影响主线 demo。

**完成标志**：有一个可展示的小实验/调研，不是“看了一遍文章”。

### D38 · 最终 demo

- [ ] 图片/视频输入；预处理、推理、后处理、画框。
- [ ] 支持切换 backend：NumPy / CUDA float / CUDA int8。
- [ ] 输出延迟、FPS、显存。
- [ ] 录屏或保存截图。
- [ ] 准备 3 张有代表性的图：小目标、遮挡、密集场景。

**完成标志**：demo 能稳定跑；结果可展示。

### D39 · 从零讲一遍

- [ ] 写一篇总结：YOLOX 结构 → ONNX → NumPy 算子 → 量化 → CUDA。
- [ ] 每个部分回答：为什么这样做？怎么验证？遇到什么坑？
- [ ] 画一张总架构图。
- [ ] 找一个人（或对镜子）讲 10 分钟，记录卡壳的地方。
- [ ] 卡壳的地方补进笔记。

**完成标志**：能不看稿讲清楚主线；总结能给别人看。

### D40 · 复盘 + 下一个 90 天

- [ ] 复盘 40 天：完成了什么、没完成什么、为什么。
- [ ] 更新总览的进度看板和变更记录。
- [ ] 写下一个 90 天计划：方向、项目、验收。
- [ ] 清理仓库：分支、tag、README、license（如果需要）。
- [ ] 缓冲：补欠的文档/测试。

**完成标志**：有一个明确的下一阶段目标，不是“继续学”。
