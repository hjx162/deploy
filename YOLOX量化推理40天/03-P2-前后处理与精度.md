# P2 · 前后处理与精度（D7–D10）

> [!info] 阶段定位
> P1 只证明“张量算对了”；P2 证明“检测结果对了”。这一阶段把预处理、decode、NMS、mAP 和性能基线补齐，后面量化才有可比较的精度指标。

> [!note] 机器：Mac（M5 Pro）
> 本阶段全部在 Mac 上完成；不会用到 CUDA。双机同步见 [[11-双机Git工作流]]。

## 阶段目标

- 实现官方 YOLOX demo 同款预处理：letterbox、RGB、0–255。
- 实现 decode + NMS，把 1×8400×85 变成框。
- 在真实图片上和 ORT/官方 demo 对齐。
- 建立 float32 基线的 mAP 和延迟表。

## 硬验收标准

- [ ] 20 张图上检测结果与 ORT 一致率 > 95%（类别、分数、框坐标 ±1 px）。
- [ ] COCO 子集（100–500 张）mAP 与 ORT 差距 < 0.5。
- [ ] 有一张逐算子耗时表，能指出 top 5 热点。
- [ ] 预处理/后处理都有单元测试或手算样例。

> [!warning] 先确认预处理
> YOLOX 官方 demo 是 RGB、0–255、pad 114、左上角对齐。用错 BGR 或归一化，框会整体偏移，且分数会异常。

## 前置条件

- P1 的 float32 全模型输出已对齐。
- 有 20 张以上图片；最好有 COCO val 子集和标注。
- 安装 `opencv-python`、`pycocotools`（按需）。

## 每日任务

### D7 · 预处理 + decode + NMS

- [ ] `letterbox`：算 ratio、new_size、pad；用 114 填充；记录 ratio 和 pad，供反算。
- [ ] 预处理：BGR→RGB、HWC→CHW、float32、0–255，不做 mean/std。
- [ ] decode：输出顺序 80×80 → 40×40 → 20×20；stride 8/16/32。
- [ ] 公式：`xy = (raw_xy + grid) * stride`；`wh = exp(raw_wh) * stride`。
- [ ] 注意：obj/cls 在 ONNX 里已经过 sigmoid，不要再 sigmoid 一次；只 decode 前 4 维。
- [ ] NMS：conf 0.3、nms 0.45；先做多类别 NMS，再按类别筛选。
- [ ] 把框从 640 输入坐标映射回原图；画框并保存。
- [ ] 用一个手算样例验证 decode 的 grid/stride。

**完成标志**：单张图能画出合理框；坐标不整体偏移。

### D8 · 与 ORT/官方 demo 对齐

- [ ] 选 20 张图，分别跑 NumPy 和 ORT，保存检测结果。
- [ ] 对比类别、分数、框坐标；统计一致率。
- [ ] 如果不一致，按顺序查：预处理颜色/归一化 → letterbox → 输出顺序 → decode → NMS → 坐标反算。
- [ ] 用官方 `demo_postprocess` + `multiclass_nms` 作为第二参考。
- [ ] 记录 3 个最典型的不一致案例。

**完成标志**：一致率 > 95%；剩余差异能解释（如 NMS 边界、分数阈值）。

### D9 · COCO 子集 mAP

- [ ] 选 100–500 张 COCO val 图片和标注。
- [ ] 用 pycocotools 算 mAP@0.5:0.95、mAP@0.5。
- [ ] 同时跑 ORT 作为对照，记录差距。
- [ ] 保存预测 json，便于复现。
- [ ] 注意：子集 mAP 只用于相对比较，不要和官方完整 COCO 40.5 直接比。

**完成标志**：有 float32 基线的 mAP 数字；与 ORT 差距 < 0.5。

### D10 · 性能剖析 + 缓冲

- [ ] 给每个算子加计时（至少 Conv/Concat/Resize/MaxPool/Sigmoid/Mul）。
- [ ] 输出 top 10 耗时层；计算每层 FLOPs 和实际 GFLOPS。
- [ ] 优化明显的拷贝/临时张量；复用 buffer。
- [ ] 写一页 `docs/P2-float-baseline.md`：mAP、延迟、top 热点、已知问题。
- [ ] 缓冲：补前面欠的测试或笔记。

**完成标志**：有一张可解释的性能表；知道 P3 量化后该对比哪些指标。
